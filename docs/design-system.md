# Design system

How pages on the ai-jail site are put together. Read this before adding or changing a page.

## The idea

The site is printed like a Brazilian cordel: black ink on unbleached paper, a woodcut padlock for a logo, wood-type headlines, typewriter labels, and six flat spot colors laid down like cheap color plates, slightly out of register. Nothing glows, nothing blurs, nothing fades in. Depth comes from a hard offset shadow, hierarchy from rules and type, color from one plate per subject.

Three things carry meaning everywhere:

1. The teal plate is the agent and what it may reach. It is also under the one primary button.
2. The red hatching is what is blocked, and the red stamp is what the product is not.
3. The bars are the window of the padlock: `.bars` next to a heading, the wall around a diagram, the cell bars over the project tile in the home scene.

Why this and not the previous neon look: `docs/research/design-study.md`.

## Spot colors

| Subject | Hue | `data-hue` |
|---|---|---|
| Do I need it? (risk, the reader's situation) | rose | `rose` |
| How it works (layers, kernel features) | clay | `clay` |
| What you turn on (configuration, opt-ins) | mustard | `mustard` |
| Compare (other tools) | indigo | `indigo` |
| Security, limits, anything blocked | red | `red` |
| The agent, install, download, the one action | teal | `teal` |
| Spare, for a panel that needs telling apart | sage | `sage` |

Put `data-hue="mustard"` on an element and its children can use `var(--hue)` (the ink variant, for text and rules), `var(--hue-soft)` (the plate, for blocks) and `var(--hue-vivid)` (the plate as printed, the same in both themes, never for text). Never write a color value in a page or component: only tokens from `src/styles/global.css`, generated by `scripts/build-palette.mjs`. See [color-study.md](color-study.md).

Three states recur across the site and always look the same (`Reach` component, the diagrams, the home scene): inside the jail (teal plate), out of reach (red hatching), off until you ask (mustard plate).

## Each page has a face

The pages share one material, so each hero carries one ornament of its own, drawn in `PageHero` from the `page` prop, with no extra text: a reader should know which page this is from the top of it. Keep one ornament per page and keep it in the hero; the body of every page uses the shared components.

| Page | Ornament |
|---|---|
| Do I need it? | the title printed on a rose poster plate, slightly out of register |
| How it works | the five nested layers, as rings in the corner |
| Compare | ruled ledger paper with an indigo margin line |
| Configure | a row of switches under the lede, some on |
| Security | a red hatched warning band along the start edge |
| Install | a punched ticket on the teal plate |
| Download | a parcel label: double border, outline, offset shadow |
| Home | the woodcut on two misregistered plates with the "Not a VM" stamp, and the scroll scene |

## Type

Alfa Slab One for headlines, set in capitals; Lora for body; Courier Prime for labels, buttons, navigation, kickers and code. Hebrew, Japanese and Korean use their own heavy sans faces for headlines (`:lang()` rules in `global.css`) and are not capitalized. Sizes are Tailwind utilities backed by tokens: `text-4xl` (page h1), `text-3xl` (section h2), `text-2xl`, `text-xl` (h3), `text-lg` (lede), `text-base`, `text-sm`.

- Headlines are capitals because the face is wood type. Everything else is sentence case.
- A headline is one color. Do not color or italicize one word of it.
- Body lines stay under about 70 characters (`.lede`, `.prose-site`, or `max-w-[40em]`).

## Layout

- `.wrap` is the 74rem column, `.wrap-narrow` is 50rem for reading. `.band` is the vertical rhythm.
- Left aligned. Nothing is centered except the CTA band.
- A section opens with a heavy rule (`.rule`) and the bars; a page hero closes with a double rule (`.rule-double`); lists divide with a thin rule (`.rule-thin`). These three rules and the offset shadow (`--press`) are the whole ornament.
- Blocks are `.cell`: a 3px ink border, the subject's plate, the offset shadow. Terminals are the same block on ink.
- Mobile first. Every grid collapses to one column. Tables and diagrams scroll sideways inside their frame. The page must never scroll sideways at 360px.
- CSS uses logical properties (`margin-inline-start`, `ms-4`, `text-start`) so Hebrew mirrors. Terminals, diagrams and file paths get `dir="ltr"`.

## Components (`src/components`)

| Component | Use |
|---|---|
| `Base` (layout) | Every page. Props: `title`, `description` (140 to 160 characters), `schema`. |
| `PageHero` | Top of every detail page. Props: `hue`, `page`, `kicker` (`t('kicker.<page>')`), `title`, `lede`. Slot: one or two buttons. `page` picks the page's own ornament, see below. |
| `Section` | A chapter with a rule and an h2. Props: `title`, `lede`, `hue`, `id`, `tint`, `narrow`, `ink` (always-ink band). |
| `Diagram` | A drawing in code. Props: `name` (file in `src/components/diagrams/`, key in `images.json`), `alt` (say what the drawing says), `caption`. See [images.md](images.md). |
| `FeatureGrid` | Two to six short points as cells. Props: `items[{title,text,hue,href,link}]`, `cols`. |
| `Reach` | What the agent can touch. Props: `items[{text,state}]`, `state` (`inside`, `blocked`, `optin`), `title`. |
| `Steps` | A numbered procedure with terminals. Props: `steps[{title,text,code,codeTitle}]`. |
| `CodeBlock` | A terminal with a copy button. Props: `code`, `title`. Lines starting with `#` dim. |
| `Tabs` | Props: `id`, `labels[]`. Panels are slots named `"0"`, `"1"`... |
| `Facts` | A strip of verified numbers. Props: `items[{n,label}]`. Numbers come from `src/data/facts.json`. |
| `Callout` | Limits and caveats, a cell on the red plate by default. Props: `title`, `hue`. |
| `Faq` | Accordion fed by the same list as `faqPage()`. Props: `items`, `title`, `hue`. |
| `NextPages` | Two or three onward links. Props: `title` (`t('next.title')`), `items[{title,text,hue,href}]`. |
| `CtaBand` | The closing call to action. |
| `Lockdown` | The homepage scroll scene. Do not reuse. |

Classes in `global.css`: `btn btn-primary`, `btn btn-ghost`, `cell`, `lede`, `kicker`, `badge`, `bars`, `stamp`, `rule`, `rule-double`, `rule-thin`, `reach`, `ticks`, `table-wrap` + `table-site`, `prose-site`, `link`, `on-ink`. A page's own `<style>` is for what only that page has.

A detail page is: `PageHero`, three to six `Section`s with at least two `Diagram`s, an optional `Faq`, `NextPages`, `CtaBand`.

## Motion

One orchestrated moment on the whole site: the home scene (`data-scene`, `src/scripts/motion.ts`), a tall section with a sticky stage that gets `data-step` from the scroll position while CSS does the rest. Nothing else moves on scroll. Hover states are a shift of the offset shadow. Everything is off under `prefers-reduced-motion`, and the content is complete without JavaScript.

## Writing

The reader has never heard of ai-jail and may not know what a sandbox is. Tell them what it does for them, then how.

- Short. A section is a heading, one or two sentences, and something to look at. If a paragraph passes three sentences, it wants to be a list, a table or a diagram. Prefer a `Diagram` to a paragraph.
- Plain verbs, second person, active voice. Explain a term the first time it appears ("Landlock, a Linux kernel feature that...").
- Facts come from the ai-jail repository (README, `docs/SECURITY.md`). Facts about other products come from `docs/research/builtin-sandboxes.md`, `docs/research/codex-antigravity.md` and `docs/research/nono-zerobox.md`, which has sources. Do not invent numbers, features or quotes. Link to the vendor's documentation when describing their product and say "at the time of writing".
- Be fair to other tools and honest about limits. Since 2.6 the README frames ai-jail as an accident guard for a trusted-but-fallible agent, tuned for developer convenience (the agent's own login and your toolchains are on by default), and says plainly that it is not a boundary against hostile code or a motivated attacker: a disposable VM is. The site uses that framing. The facts about what is hidden (home, keys, shell secrets, network) stay, because they are still true.
- No em dashes or en dashes. No "not X, but Y". No three-item lists for rhythm. No closing one-liners that restate the section. No "seamless", "robust", "powerful", "unlock", "effortless", "key", "crucial", "landscape", "peace of mind". No arrows or emoji in text.
- Say a thing fully in one place and link to it from the others. Canonical homes: risk scenarios on Do I need it; binaries, checksums and release notes on Download; the layers and macOS differences on How it works; other tools on Compare; commands to install and the first run on Install; every flag, config key, masking and lockdown on Configure; threat model, weakening opt-ins, audits, release signing and reporting on Security. A short limit the reader must see before acting may repeat.
- Do not claim: that ai-jail is a security boundary against hostile code, protection from kernel exploits, that it replaces a VM, third-party audits (the published audits are the project's own), that the host allowlist inspects content or blocks UDP and DNS on macOS (it is TCP and CONNECT only; see the Security page), Windows support.

## Languages

Every visible string lives in `src/i18n/locales/`, never in an `.astro` file. Structure (hues, hrefs, ids, commands, flags) stays in code; words go in the catalog; `withText()` joins them. See [i18n.md](i18n.md).

## Images

The logo is a woodcut (`docs/brand/`). Every diagram is drawn in code and takes its labels from the catalogs. See [images.md](images.md).
