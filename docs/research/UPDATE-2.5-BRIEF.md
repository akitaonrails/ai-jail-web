## What changed, all opt-in except where said

1. **Dev toolchains, on by default (2.5.0, Linux).** `--toolchains` / `--no-toolchains`, key `no_toolchains = true` to disable. ai-jail maps a jail-owned cache store at `~/.local/share/ai-jail/cache/` so dependency caches survive across sessions. Rust: `~/.cargo/bin` and `~/.rustup` mounted read-only so `cargo` and `rustc` resolve; `~/.cargo/registry` and `~/.cargo/git` bound to the jail store; `~/.cargo` credentials and `config.toml` never mapped; `cargo install` to the global bin unsupported in-jail (use `cargo install --root`). Other ecosystems get a jail-owned cache at their default path when the tool's home dir exists on the host: `~/.cache` (pip, uv, go-build, yarn, deno, coursier, crystal, zig, composer), `~/go/pkg/mod`, `~/.npm`, `~/.m2/repository`, `~/.gradle/caches`, `~/.bun/install/cache`, `~/.local/share/pnpm/store`. The host's real caches are never bound, so a jailed build cannot poison what the host builds from. Disabled under `--lockdown`. A project `.ai-jail` can only disable it.
2. **Default filtered egress to package registries (2.5.0).** When toolchains are on and the network posture is otherwise unset (no `--network`, no `--no-network`, not lockdown, not a browser launch), ai-jail default-allows filtered egress (the same CONNECT proxy as `--allow-host`) to exactly: `crates.io`, `registry.npmjs.org`, `registry.yarnpkg.com`, `pypi.org`, `files.pythonhosted.org`, `proxy.golang.org`, `sum.golang.org`, `repo1.maven.org`, `repo.maven.apache.org`, `repo.clojars.org`, `repo.packagist.org`, `github.com`, `codeload.github.com`, `objects.githubusercontent.com`. An entry matches the host and its subdomains. Nothing else is reachable. An explicit `--allow-host` list is unioned with it and keeps its fail-closed guarantee. Gated on an unprivileged network-namespace probe: where netns is unavailable the default silently stays offline. `--no-network` keeps the sandbox fully offline; `--no-toolchains` turns off both the caches and the registry default. The agent's own API (api.anthropic.com etc.) is still NOT covered: it needs `--allow-host` or `--network`. This softens "network off by default" for the toolchain case only, always filtered, never unrestricted.
3. **mise works out of the box (2.4.1).** When mise is enabled (default), ai-jail maps the mise data dir (`~/.local/share/mise`, honoring `MISE_DATA_DIR`), config dir (`~/.config/mise`, honoring `MISE_CONFIG_DIR`) and the `mise` binary's directory read-only, automatically, only when they exist; never persisted to a saved `.ai-jail`. `--no-mise` and `--lockdown` opt out. The old advice to map mise dirs by hand is obsolete.
4. **Tool credential passthrough, off by default (2.5.0).** `--github` (`~/.config/gh`), `--aws` (`~/.aws`), `--kube` (`~/.kube`), `--gcloud` (`~/.config/gcloud`), `--docker-config` (`~/.docker/config.json`); keys `github`, `aws`, `kube`, `gcloud`, `docker_config` (= true). Each mounts that tool's credentials read-only. Read-only protects the file from modification, not the credential from use: anything in the sandbox can act as you on that service while the credential is valid. Monotonic (a project file may only disable), disabled under `--lockdown`. The GitHub CLI also needs to reach `api.github.com`, which the default registry list covers through `github.com`.
5. **`--kvm` / `--no-kvm` (2.5.0, Linux), key `kvm = true`.** Passes `/dev/kvm` through for hardware-accelerated virtualization (QEMU, Firecracker, Android emulator). Bound only when it is a character device; off by default; disabled under lockdown; no `/dev/net/tun` or vhost devices, guests get only the sandbox's network. Contributed by @thomaswiese.
6. **`ai-jail --audit-show` (2.3.0).** Prints a readable local summary of launches, filtered-network decisions and credential substitutions. Exit 0 after a display (an empty log too), 1 for malformed records or an I/O or security error, 2 when the log does not exist. It does not verify the chain; `--audit-verify` does. Launch summaries may show command arguments, so avoid secrets in argv. Audit readers and writer share safe-open hardening (no symlink followed below HOME, special files and foreign-owned or group/other-readable logs rejected, bounded record size). Audit-log failures are best-effort: logging is disabled with a warning, the launch continues; no fallback log under /tmp.
7. **2.4.0 security release** closed two GitHub advisories (GHSA-w976-gw52-hvx2 with five findings, GHSA-frgp-q3qc-g78p) found by two independent source audits on 2026-09-30, published in the repository (`docs/SECURITY_AUDIT_2026-09-30.md`, `_B.md`, comparison and remediation plan). Audit A states it was performed by an AI model (LUA, a Genesys PI model by LUA Vision); audit B was an independent second audit. Say "two independent source audits, published in the repository" and that they are not a third-party firm engagement. Fixes: worktree metadata can no longer bind an arbitrary host directory read-write; duplicate env entries no longer defeat phantom-secret injection; a browser command from an untrusted project can no longer clear lockdown; TIOCSTI is compared as the kernel reads it (32-bit), closing a high-bit bypass; Landlock scopes abstract Unix sockets and signals on kernels 6.12+ (ABI V6, best-effort); macOS terminal read/write scoped to this run's own terminals; macOS `--mask` paths denied for writes too; the escape filter no longer collapses on a doubled ESC (OSC smuggling); proxy test hatches compiled out of release builds. Changed, fails closed: overlay setup failures now abort the launch instead of silently falling back to the plain read-write bind. New regression tests for each.
8. **2.5.0 fixes:** Landlock no longer blocks cross-directory rename (EXDEV) which had broken Rust builds in the jail; flags after `--` go to the child verbatim; `--env-from-file` is read through a validated descriptor (TOCTOU closed), contributed by @Josehbr.
9. **2.2.1:** launch warning when `opencode` runs without `--standalone` (opencode 2.x uses a shared background server that cannot persist in a one-shot jail with a tmpfs home; pin `command = ["opencode", "--standalone"]`); nested command mount fix (#138); AUR LTO fix.
10. Known agents with an API host for the warning: claude, codex, gemini, grok (api.x.ai).

## Consequences for the site

- Everywhere the site says the network is off by default, say: off, except a short list of package registries reachable through the filtered proxy when toolchains are on (the default on Linux), and `--no-network` makes it fully offline. The agent's API is still closed until `--allow-host` or `--network`.
- "Every capability is off until you turn it on" is no longer exact: toolchains (and mise since 2.4.1) are on by default and additive. Say so where defaults are listed.
- Diagrams: `how-egress` (Off / Filtered / Open) is still right as the three modes; add text that "Off" now means "registries only" when toolchains are on. A new diagram `configure-toolchains` is made by the Configure owner. Put new image labels into `src/i18n/locales/en/images.json`.
