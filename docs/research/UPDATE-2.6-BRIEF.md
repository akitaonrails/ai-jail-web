## What changed

1. **Purpose reframed (2.6.0, docs).** The README now opens with: ai-jail is an accident guard for a trusted-but-fallible agent, not a hard-security boundary and not a defense against malware or a motivated attacker trying to escape. Its job is to keep a mistaken agent (a mistyped `rm`, a script that walks above the project root, a package manager touching the wrong place) inside the project, so that running a harness in auto-accept "YOLO" mode is reasonable. Defaults are tuned for developer convenience, with flags to turn capabilities down, up to `--lockdown`. For hostile code or untrusted workloads: a disposable VM. The site must adopt this framing everywhere it describes what ai-jail is for: keep the facts about what is hidden (home, keys, shell secrets, network) because they are still true, but stop implying ai-jail is built to resist an attacker. Wording to reuse: "built to stop a trusted agent's mistakes", "the project directory is the blast radius", "not a boundary against hostile code".
2. **Agent login on by default (2.6.0).** `agent_state` is now ON: a plain `ai-jail claude` mounts the invoked harness's own credential/state directory read-write (claude `~/.claude` + `~/.claude.json`, codex `~/.codex`, opencode `~/.config/opencode` + `~/.local/share/opencode`, crush `~/.config/crush` + `~/.local/share/crush`, kimi `~/.kimi` (was `~/.kimi-code`, kept as alias), gemini `~/.gemini`, antigravity `~/.gemini` (new, shares Google OAuth), grok `~/.grok`, pi, others), so it starts pre-authenticated and OAuth tokens persist. When agent state is on, the harness's well-known API-key env var is also copied from the host when set: `ANTHROPIC_API_KEY` (claude), `OPENAI_API_KEY` (codex), `GEMINI_API_KEY`/`GOOGLE_API_KEY` (gemini, antigravity), `XAI_API_KEY` (grok), `MOONSHOT_API_KEY` (kimi); never persisted; an explicit `--env` wins. `--no-agent-state` gives the isolated, logged-out run; `--lockdown` always disables it; browser profiles disable it; a project `.ai-jail` can only disable it. Trade-off stated by the docs: anything in the sandbox can use those credentials for the life of the launch. So the "two things a cloud agent needs" become one: the network route (`--allow-host api.anthropic.com` or `--network`); the login is already there.
3. **Lockdown always isolates the network namespace, even with `--network` (2.6.2).** The old statement "on Linux `--network` still overrides lockdown" is false now. Lockdown with `--allow-host` still tunnels through the proxy. `--no-network` with `--allow-host` composes to filtered egress (not a contradiction).
4. **Toolchains are Linux only (2.6.0 fix).** The cache maps and the registry default do not apply on macOS (seatbelt cannot express alternate destinations); macOS is fully offline by default. Say "on Linux" wherever the site describes them.
5. **`--env` and `--env-from-file` values no longer land on bwrap's argv (2.6.2)**: passed through an in-memory file; `--secret` remains the tool for a value that must stay out of the sandbox environment too. One clause at most, on Configure.
6. **mise:** `MISE_NOT_FOUND_AUTO_INSTALL=false` is set inside so a missing tool fails once instead of spamming (one clause in the toolchains section is enough, optional).
7. **"Turning it down" (README):** selective opt-outs `--no-agent-state`, `--no-toolchains`, `--no-network`, `--mask`/`--deny-path`, `--hide-dotdir`, narrow `--map`/`--rw-map`; `--no-private-home` is MORE exposure; `--lockdown` is the maximum (read-only project, toolchains, agent state, registry egress and most capabilities off, strict Landlock and seccomp), still not a VM.
8. Known agents for warnings unchanged (claude, codex, gemini, grok hosts). `--ro-map` is an alias for `--map` (no need to document).

## Consequences for the site

- Every "`--agent-state` is opt-in / off by default" statement and every recipe that passes `--agent-state` or sets `agent_state = true` must change: drop the flag from recipes (it is the default), present `--no-agent-state` as the opt-out, and mark the switch as on by default (Configure already has an "On by default" badge: risk `default`).
- Every "two things a cloud agent needs" (login + API host) becomes one thing (the API host). The install-first-run diagram shows two gates; the Install owner regenerates it with the login card inside the cell and one gate for the API host.
- "Tokens and API keys in your shell stay outside": still true, except the invoked harness's own key, copied by default. Say so where the environment allowlist is described (Home blocked list, How it works env layer, Security "secrets in your shell").
- Hero, Why, Security and Compare TLDR adopt the accident-guard framing. Why page's scenarios (prompt injection, malicious package, honest mistake) stay, but the page must say that the first two are where ai-jail limits the damage without being built to resist a determined attacker, and the third is what it is for.
