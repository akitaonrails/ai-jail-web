# nono and zerobox: sandbox facts for the Compare page

Reviewed 2026-09-24. Official sources only (repositories, docs sites, release pages). Anything not stated in a primary source is marked UNVERIFIED. ai-jail 2.2 credits both for phantom credentials (`--secret KEY=host`) and the hash-chained audit log (`--audit-verify`), see https://github.com/akitaonrails/ai-jail/issues/135 .

## 1. nono

- What: "agent runtime security - zero trust, zero setup, zero latency". Repo https://github.com/nolabs-ai/nono (moved from `always-further`), site https://nono.sh . Made by nolabs (Luke Hinds, Stephen Parkinson, "built by Sigstore team" on the README). Rust, Apache-2.0, created 2026-01-31, 4.2k stars. Latest release v0.78.0, 2026-09-16, with four security advisories in the notes; v0.77.0 removed legacy aliases "for v1.0.0 prep". https://api.github.com/repos/nolabs-ai/nono , https://github.com/nolabs-ai/nono/releases
- Platforms: macOS, Linux, Windows via WSL2. Install: curl script, Homebrew, Nix flake, deb/rpm/Arch. No daemon, container or VM. https://github.com/nolabs-ai/nono
- Primitives: Linux Landlock (5.13+ basic, 6.2+ full filesystem, 6.7+ TCP filtering) plus seccomp that traps only `openat`/`openat2` (user notification) and, with `--block-net`, denies Internet sockets and `io_uring_setup()`; macOS Seatbelt via `sandbox_init()`. "No mount namespaces (noted as optional future improvement)". Restrictions are irrevocable for the child and its descendants. https://nono.sh/docs/cli/internals/security-model , https://nono.sh/docs/cli/internals/landlock , https://nono.sh/docs/cli/features/networking.md
- Boundary: the tool invocation. A supervisor (nono's own binary, unsandboxed, same user, no setuid) launches "a fresh child sandbox" per command; chained commands (git then ssh) cross the broker again and get their own policy. `nono run --profile claude-code -- claude` wraps the agent process as such a child. https://nono.sh/docs/cli/internals/security-model
- Filesystem defaults: only granted paths; profiles are "intentionally narrow", most grant read+write on cwd, agent profiles add `~/.claude` or `~/.codex`; `$HOME/.ssh` and other credential dirs are in deny groups and not granted. `stat()`/`access()` are not trapped, so the sandbox can enumerate paths it cannot open. https://nono.sh/docs/cli/features/profiles-groups.md , https://nono.sh/docs/cli/internals/security-model
- Environment: "By default, sandboxed processes inherit all environment variables from the parent process"; `allow_vars`/`deny_vars` in profiles; `LD_PRELOAD`, `DYLD_INSERT_LIBRARIES`, `PYTHONPATH`, `NODE_OPTIONS` always blocked. https://nono.sh/docs/cli/features/environment.md
- Network: unrestricted by default. `--block-net` (kernel filter). `--allow-domain` starts a CONNECT proxy (raw TCP relay, "the proxy never sees plaintext", wildcards, path-scoped URLs, DNS rebinding check) and sets `HTTP_PROXY`/`HTTPS_PROXY` plus a 256-bit session token in `Proxy-Authorization`/`X-Nono-Token`; on Linux a seccomp user-notification layer checks the real `connect()` destination. `--allow-endpoint` (method and path globs) turns on TLS interception with an ephemeral CA per run. Cloud metadata and link-local always denied. WSL2 domain filtering is opt-in and marked insecure. https://nono.sh/docs/cli/features/networking.md
- Credentials: `--credential <service>` runs a reverse proxy at `localhost:<port>/<service>/...`, rewrites `OPENAI_BASE_URL`/`ANTHROPIC_BASE_URL` into the child, and injects the real key as header, URL path, query or Basic auth. The child holds only the session token (`OPENAI_API_KEY=nono_sess_...`); requests without it get 401. Sources: keyring, `op://`, `bw://`, `file://`, `env://`, `cmd://`. Caveats: SDK must honor a base-URL variable, upstream must be HTTPS, blocked by default on WSL2, Go tools on macOS need `--trust-proxy-ca`. `--env-credential` is the weaker alternative that puts the real value in the env. Sandboxed OAuth logins rewrite provider token responses into phantoms (`nono_<64hex>` or synthetic JWT) that resolve only through declared `credential_routes`. https://nono.sh/docs/cli/features/credential-injection.md , https://nono.sh/docs/cli/features/sandboxed-oauth-logins
- Audit: per-session records in `~/.local/state/nono/audit/` with "a hash-chain head over the ordered event stream, and a Merkle root over all recorded event leaves", optional filesystem Merkle roots and rollback snapshots, optional per-session DSSE signature (`audit-attestation.bundle`). Commands: `nono audit list|show|verify|cleanup`. Caveats: ledger corruption stops recording with no repair, proxy events finalized post-session, only the main executable hashed. https://nono.sh/docs/cli/features/audit.md
- Approvals: supervised execution is the default; with `--capability-elevation` a denied `openat` pauses and prompts "[nono] claude wants to read ... Allow? [y/N]", then the supervisor injects the fd (`SECCOMP_IOCTL_NOTIF_ADDFD`). Linux only; "Capability expansion is not available on macOS". Webhooks "planned". https://nono.sh/docs/cli/features/supervisor
- Agents: JSON profiles `default`, `claude-code`, `codex`, `opencode`, `openclaw`, language profiles, plus a registry (registry.nono.sh, `nono search|pull`). Command policies restrict argv patterns and endpoints. Python and TypeScript libraries, SPIFFE/SPIRE identities. https://github.com/nolabs-ai/nono , https://nono.sh/docs/cli/features/spiffe.md
- UNVERIFIED: MCP-specific handling (not in the docs index); whether the whole agent process is always the same child as its tool calls in `nono run`.

## 2. zerobox

- What: "Lightweight, cross-platform process sandboxing powered by OpenAI Codex's sandbox runtime. Sandbox any command with file, network, and credential controls." Repo https://github.com/afshinm/zerobox , one author (afshinm). Rust, Apache-2.0, created 2026-03-17, 718 stars, last push 2026-05-17. Latest release v0.3.3, 2026-05-17 (bwrap entrypoint fix). Distributed on npm, PyPI, crates.io with SDKs in each. https://api.github.com/repos/afshinm/zerobox , https://api.github.com/repos/afshinm/zerobox/releases
- Platforms and primitives: macOS Seatbelt (`sandbox-exec`); Linux bubblewrap + seccomp + namespaces, taken from the Codex repository; Windows "planned". About 10 ms and 7 MB per invocation. No daemon. https://github.com/afshinm/zerobox , https://news.ycombinator.com/item?id=47574871
- Boundary: one command per invocation (`zerobox -- claude`), also per tool call from the SDK ("parent agent process running normally"); an example wraps the whole agent with secrets. https://github.com/afshinm/zerobox
- Filesystem: "Deny by default: Writes, network, and environment variables are blocked unless you allow them"; `--allow-write=.`, `--allow-read`, `--deny-read`, `--deny-write`. Reads are allowed by default (author on HN, "Deno's model"). Home visible, `~/.ssh` readable unless `--deny-read`: UNVERIFIED, inferred from the flag set. `--snapshot`/`--restore` and `zerobox snapshot list|diff|restore`. https://github.com/afshinm/zerobox , https://news.ycombinator.com/item?id=47574871
- Environment: only `PATH, HOME, USER, SHELL, TERM, LANG` inherited; `--env`, `--allow-env`, `--deny-env`. https://github.com/afshinm/zerobox
- Network: off by default; `--allow-net` or `--allow-net=domain`, `--deny-net`. A proxy intercepts HTTPS to inject secrets (author: "MITM proxy"); on macOS filtering depends on the process honoring proxy env vars. CA handling: UNVERIFIED. https://news.ycombinator.com/item?id=47574871
- Credentials: `--secret KEY=VALUE` gives the process `ZEROBOX_SECRET_<hash>`; `--secret-host KEY=HOSTS` restricts substitution to those hosts; without it "the secret is passed to all domains". Node needs `--use-env-proxy`. https://github.com/afshinm/zerobox
- Audit, approvals, presets: none. `--debug` prints proxy decisions to stderr; an `zerobox-otel` crate exists (UNVERIFIED scope). Author said profiles and interactive approval are planned. https://github.com/afshinm/zerobox/tree/main/crates , https://news.ycombinator.com/item?id=47574871

## 3. Summary

- nono does, ai-jail does not: per-tool child sandboxes with argv and endpoint policies, runtime approvals with fd injection, keyring and OAuth-backed phantom tokens, Merkle root plus signed attestation, profile registry, SDKs, SPIFFE.
- ai-jail does, nono does not: mount and PID namespaces with a fresh empty home, network off by default, environment allowlist by default, macOS host IPC denial, terminal output filter, rlimits, one binary with no policy language.
- zerobox does, ai-jail does not: SDK per-tool-call sandboxing from Node/Python/Rust, filesystem snapshot and restore, per-host secrets for every domain at once.
- ai-jail does, zerobox does not: hidden home and `~/.ssh` by default, Landlock second layer, audit log with verification, agent presets, lockdown mode, active releases (zerobox last pushed 2026-05-17).
- Both: Apache-2.0, Rust, no daemon, no VM, same-kernel threat model.
- nono is the closest in ambition; zerobox is the closest in flag shape (`--secret`, `--secret-host`).
- Neither hides the real home by default on Linux the way ai-jail does (nono: grants only; zerobox: reads open).
- All three rely on the client honoring proxy or base-URL variables for credential injection.

## 4. eshlox.net, "Choosing an AI sandbox" (structure, for a TLDR)

- Opens with a ranked TLDR: "most secure" (sbx Docker microVM), "easiest" (zerobox), "honorable mention" (nono), each with one command line and its distinguishing features. https://eshlox.net/choosing-an-ai-sandbox
- One section per tool (nono, zerobox, sbx, Others), each headed by a one-phrase verdict ("kernel-level, irrevocable", "clean environment, per-host secrets").
- Per tool it states in prose: maturity and version, the isolation mechanism, env and secrets handling, audit and rollback, what is missing ("No built-in profiles. No atomic rollback. No audit trail.").
- No table; the criteria are consistent but implicit.
- "Which one to pick" gives two recommendations by situation, then a closing risk section on cloud inference.
- Snapshot dates it: nono "Alpha (v0.7.0)", zerobox "v0.1.7, 7 stars", so its facts are older than this note.
