# Make ai-jail Look Like Its Mechanism

**ai-jail should be rethought as an inspectable boundary manual built from real commands, policy states, paths, layers, and dated evidence.** The current site already owns a distinctive idea: warm colors are the jail, cyan is the agent and its permitted action, and bars mean a blocked boundary. That system should remain. The generic impression comes from the presentation placed around it: a logo floating over a blurred glow, parallax and scroll recession, repeated fade and zoom effects, rounded three-column grids, and a large family of dark neon raster illustrations. Those devices make a technically candid product resemble a category template. The redesign should replace atmosphere with proof, use bars as structural boundaries rather than decoration, and make every major claim traceable to a command, state matrix, numbered technical figure, dated fact, or canonical documentation link. Accessibility and localization become easier when diagrams are built from semantic HTML and restrained inline SVG, with visible localized explanations and stable left-to-right technical tokens. The result should feel calm, authored, and specific to a whole-process sandbox for trusted coding agents, while retaining the established statement that hostile code requires a disposable virtual machine.

## Executive diagnosis: the product is specific, while its presentation is generic

The site has a stronger foundation than its current visual expression suggests. Its design system assigns stable jobs to color: the warm spectrum represents walls, rules, layers, and limits; cyan represents the agent, what the agent may reach, and the only primary action; red bars mean blocked; gold marks explicit opt-in; and cyan marks inside the jail. The palette is derived from the logo in OKLCH, checked for contrast, mirrored across light and dark themes, and separated from the inverse palette used by ai-memory (`docs/design-system.md:5-27`; `docs/color-study.md:1-69`). This is product-specific identity with a factual rationale. It should be deepened rather than discarded.

The problem is that the page grammar often places this semantic system inside a familiar generated-technology shell. The homepage uses a large logo over a blurred spectrum glow, gives that object parallax, recedes the hero as the reader scrolls, reveals content with standard fade-and-rise motion, and follows with a long sticky scene (`src/pages/[...locale]/index.astro:25-43`; `src/scripts/motion.ts:20-117`). The image direction calls for slightly isometric vector scenes, a dark maroon ground, soft neon glow, and geometric labels (`scripts/prompts/_style.txt:1-8`). Every generated figure is then presented inside the same rounded dark frame, with a shadow and a scale-up zoom (`src/components/Figure.astro:19-29`). Each device is coherent in isolation. Together they reproduce the exact bundle that practitioners associate with generic AI and security marketing: dark neon surfaces, glows, isometric objects, repeated cards, centered visual spectacle, and low-information motion ([Gajjar](https://prg.sh/ramblings/Why-Your-AI-Keeps-Building-the-Same-Purple-Gradient-Website); [AGR Studio](https://agr.studio/blog/how-cybersecurity-companies-earn-trust-with-design); [Shadow Digital](https://www.shadowdigital.cc/resources/best-cybersecurity-website-design-examples)).

The redesign therefore needs a subtraction strategy before it needs a new style. Remove ambient glow, routine parallax, routine zoom, repeated fade-up reveals, and isometric depth that does not explain topology. Reduce pill shapes and rounded containers to controls and genuinely bounded objects. Keep a single purposeful state transition where it teaches the containment model. Replace most generated raster scenes with small proof units and numbered technical plates. A developer should be able to point at every expressive choice and say what product fact it carries.

The content framing is already substantially correct. The homepage says that the agent runs under the user's account, that the project remains writable, and that keys, shell secrets, and the rest of the home directory are absent. It also states that ai-jail is an accident guard for a trusted agent, shares the host kernel, cannot contain hostile code as a security boundary, and calls for a disposable virtual machine in that case (`src/i18n/locales/en/home.json:3-7,59-62`). The redesign should preserve this wording model and move the scope limit closer to the first proof. It should never imply a fully sealed cage, independent kernel, content-aware host filtering, native Windows support, or protection against a motivated attacker (`docs/design-system.md:86-96`).

## Sourced design tells: contextlessness makes the site feel generated

The strongest genericity signal is contextlessness. Current practitioner critiques repeatedly identify purple or blue gradients, generic sans typography, centered heroes, uniform card grids, universal rounded corners, floating product panels, glass effects, tiny monospace labels, and repeated fade motion as a recognizable template bundle. The same sources stress that none of those techniques is intrinsically defective. They become a tell when they appear regardless of the product ([Gajjar](https://prg.sh/ramblings/Why-Your-AI-Keeps-Building-the-Same-Purple-Gradient-Website); [Beaver Builder and Paul Lacey](https://www.wpbeaverbuilder.com/avoid-ai-slop-in-web-design/); [Overpass Studio](https://www.overpass.studio/blog/why-saas-websites-look-the-same)). A current commercial developer-tool template even packages terminal styling, CRT effects, live typing, feature grids, and git-log presentation as one reusable skin, which means terminal aesthetics alone no longer prove authenticity ([Dual7](https://www.dual7.ai/templates/websites/landing-pages/ai-developer-tool-landing/)).

ai-jail currently contains several of these tells in source. `FeatureGrid` defaults to three equal columns and applies the same bar-heading-copy treatment to each point (`src/components/FeatureGrid.astro:1-25`). `Figure` gives every image the same rounded frame, shadow, dark ground, and zoom behavior (`src/components/Figure.astro:19-29`). `motion.ts` offers word-fill, zoom, parallax, reveal, path drawing, count-up, hero recession, a sticky scene, and focus-list dimming, with many effects reused throughout the pages (`src/scripts/motion.ts:20-117`). The homepage's visual hierarchy is a left-aligned headline next to a large floating logo and glow, followed by the 520-viewport-height Lockdown sequence (`src/pages/[...locale]/index.astro:25-43`; `src/components/Lockdown.astro:63-80`). The composition is more thoughtful than a generic centered hero, yet the glow, floating brand object, and continuous scroll theater still carry category-default signals.

The raster illustration system intensifies this effect. The common prompt specifies slightly isometric objects, soft neon glow, dark ground, large geometric shapes, and short labels (`scripts/prompts/_style.txt:1-8`). The product semantics inside those images are valuable, but the visual treatment resembles the security category's glowing cages, chips, clouds, and infrastructure diagrams. Security design practitioners specifically criticize padlocks, hacker-dark palettes, glowing globes, glitch effects, fortress language, and interchangeable threat imagery. Their recommended alternative is to derive visuals from protocol structure, policy logic, paths, and actual system behavior ([AGR Studio](https://agr.studio/blog/how-cybersecurity-companies-earn-trust-with-design); [Shadow Digital](https://www.shadowdigital.cc/resources/best-cybersecurity-website-design-examples)).

Instructional graphics research gives a firmer functional reason to change. Readers inspect task-relevant images and tend to ignore decorative filler. Google illustrates the difference with a polished chain that looks attractive but teaches the wrong linked-list structure, then recommends writing the caption first, limiting a figure to roughly one paragraph of information, simplifying repeatedly, and using progressive levels of detail ([Nielsen Norman Group](https://www.nngroup.com/articles/photos-as-web-content/); [Google for Developers](https://developers.google.com/tech-writing/two/illustrations)). The redesign should judge a figure by whether its relationships remain identifiable after removing brand color and caption. A generic cage or chip fails that test. A diagram showing an agent process, child tools, a mount namespace, a hidden home path, and one shared host kernel passes it.

Motion has the same requirement. Nielsen Norman Group recommends animation for feedback, state change, spatial continuity, and signification, while warning that unrelated movement captures attention and interferes with the task ([Nielsen Norman Group](https://www.nngroup.com/articles/animation-purpose-ux/)). WCAG 2.2 requires interaction-triggered motion to be disableable when it is nonessential and identifies parallax and scroll-triggered motion as possible causes of discomfort ([W3C, Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)). The existing reduced-motion guard is sound (`src/scripts/motion.ts:18-20`; `docs/design-system.md:69-84`). The remaining issue is editorial: too many effects communicate polish rather than state.

Distinctive developer sites provide a consistent counter-pattern. SQLite exposes documentation, current releases, dates, and situations where another database is the better choice. Zig pairs claims with real programs and compiler output. Oxide uses numbered figures, specifications, interfaces, and engineering-drawing conventions. Ladybird shows status, platform scope, source, commands, and a dated work log. Their transferable pattern is **claim, artifact, route to verification** ([SQLite](https://sqlite.org/); [SQLite appropriate uses](https://www.sqlite.org/whentouse.html); [Zig](https://ziglang.org/learn/overview/); [Oxide](https://oxide.computer/product/specifications); [Ladybird](https://ladybird.org/news/)). ai-jail already has the source material for this pattern in its commands, flags, fact file, comparisons, threat model, own audits, release notes, and platform tables. The redesign should make those materials the visual identity.

## What to retain: the parts already traceable to product truth

**Retain the palette and its semantic assignments.** The warm jail spectrum and cyan agent/action complement are more original than a replacement palette would be. The colors come from the logo, have distinct subject assignments, and already meet documented contrast targets (`docs/color-study.md:26-65,73-149`). Preserve the rule that cyan is scarce. A cyan route, process, or button should identify permission or agency. It should never become a general ambient glow.

**Retain bars as the sole ornament, then make them do more work.** Bars already mean blocked in `Reach`, appear as section rules, and derive from the logo (`docs/design-system.md:5-12`; `src/styles/global.css:126-131,151-156`). Their next use should be structural: a boundary between host and sandbox, a clipped path, a table group separator, a layer rail, or a gate in a route. Avoid sprinkling bars above every card merely as decoration. If removing bars from an element changes no meaning, that use is optional.

**Retain the three-state language.** Inside, blocked, and opt-in are already redundant across color and shape: cyan ring, red bars, and gold ring (`docs/color-study.md:57-60`; `src/styles/global.css:151-156`). This is one of the site's most useful product-specific systems. Promote it into every relevant diagram, comparison, switch table, and example. Always pair the shape and color with a visible state word.

**Retain the light-first theme with selected dark evidence surfaces.** The category is already crowded with dark security sites, while the site has a warm, high-contrast light ground and uses the dark ink surface only for terminals, diagrams, and the closing band (`docs/color-study.md:67-71`). This supports readability and makes a real terminal or constrained system view feel evidentiary. Do not make every section dark.

**Retain the type families during the first redesign phase.** Red Hat Display, Text, and Mono already separate headings, body copy, and literal code; Hebrew, Japanese, and Korean use script-appropriate families (`docs/design-system.md:29-35`; `src/styles/global.css:92-101,177-189`). A font swap would add localization risk without solving the deeper genericity. The type system should become more distinctive through role, density, line measure, labels, and figure captions. Reserve monospace for commands, flags, paths, versions, state fixtures, and observed output.

**Retain catalog-driven localization and logical layout.** All visible words live in six locale catalogs, dates and numbers are formatted, code remains left-to-right, Hebrew receives root direction and logical CSS, and CI catches stale translations (`docs/i18n.md:14-27,39-60`). This architecture is compatible with a more original site as long as visual distinction comes from repeatable semantic units rather than tightly art-directed English compositions.

**Retain the accurate content boundaries and canonical-page discipline.** The existing system assigns risk scenarios to Do I need it, mechanism and platform differences to How it works, flags and opt-ins to Configure, and threat model and audits to Security (`docs/design-system.md:86-96`). The redesign should reduce repetition, expose deep links, and keep claims close to their evidence without creating alternate explanations that drift.

## Proposed visual direction: an inspected boundary manual

The proposed direction is **an inspected boundary manual**. It should feel like a maintained technical field guide for a small system utility. The visual world consists of boundary lines, path records, process trees, policy matrices, numbered figures, shell transcripts, release labels, and inspection notes. Warm colors define the enclosing rules. Cyan identifies the active agent and the path that remains available. Red barred regions identify absence or denial. Gold marks a control the user explicitly opens. Maroon neutrals carry the page without turning every surface into a terminal.

The core content unit should become a **proof plate** with six parts: an editorial label such as “Fig. 03” or “Observed with 2.6.2,” a literal heading, one short claim, one artifact, one caption stating scope, and one link to verification. The artifact can be a live-text command and output, a semantic boundary map, a small table, a process tree, or a dated fact. This structure follows the pattern used effectively by Zig, Oxide, and Ladybird while remaining native to ai-jail's own mechanism ([Zig](https://ziglang.org/); [Oxide](https://oxide.computer/); [Ladybird](https://ladybird.org/)).

The layout should remain left-aligned and mobile-first, but section compositions should vary according to the evidence. A command can occupy a narrow column beside its result. A boundary map can span the full content width. A short decision table can follow the prose in the same reading column. An audit record can look like a dated ledger. This creates rhythm without universal cards. On wide screens, asymmetric placement may show cause on the inline start and effect on the inline end. The DOM order must always remain question, attempt, outcome, explanation, verification. Logical properties should mirror editorial placement for Hebrew, while paths, commands, and protocol geometry remain explicitly left-to-right ([W3C, structural markup and right-to-left text](https://www.w3.org/International/questions/qa-html-dir)).

Rounded forms should have narrower roles. Keep pills for compact status badges and controls. Keep rounded frames for actual terminals or bounded interactive regions. Use square or lightly softened corners for technical plates, tables, and diagrams. Replace large shadows with rules, spacing, and tonal surfaces. Remove `hero-glow`, cyan box shadows around the agent, and atmospheric blur. The color system is strong enough to work without simulated emission.

The homepage hero should place the product truth and first command before the brand image. A suitable composition is a narrow evidence rail containing current version, Linux and macOS status, GPL license, and reviewed date; a direct heading and lede; the two-line command; and a compact boundary result showing “project writable,” “home absent,” and “network filtered or closed.” The logo can remain in the header and appear once as a small annotated mark. It should no longer act as a floating decorative hero object.

Motion should use a strict budget. Keep one user-controlled or scroll-linked containment sequence on the homepage, because the change from host reach to jailed reach is a real state transition. Replace the current 520vh sequence with three or four stable states and visible step controls or a shorter sticky region. The final state must remain the no-script and reduced-motion rendering. Elsewhere, use motion only for direct feedback such as copying a command, opening details, selecting a tab, or highlighting the route affected by a chosen state. Remove default `data-zoom`, routine `data-reveal`, `data-parallax`, `data-fill`, and `data-exit` from the editorial layer. The reduced-motion behavior should produce identical information with no delayed reveal.

Voice should remain calm, specific, and candid. Dry jail vocabulary can appear in a caption or terminal comment, but security scope and navigation should stay literal. The writing system already prohibits formulaic contrast, rhythmic three-part slogans, exaggerated claims, and cinematic security language (`docs/design-system.md:86-96`). Preserve that discipline across all six languages. Humor that depends on English wordplay should be independently transcreated or omitted.

## Diagram strategy: replace mood images with verifiable system views

The site should move from a raster illustration pipeline to a data-first diagram system. The current localized WebP pipeline successfully handles six languages, but every label is embedded in an image and every figure inherits the same neon isometric treatment (`src/components/Figure.astro:1-29`; `docs/i18n.md:70-79`). Real HTML and restrained inline SVG offer better zoom, copyability, translation, text spacing, and semantic structure. W3C recommends real text where web technology can produce the presentation, and requires concise alternatives plus a complete textual equivalent for complex diagrams ([W3C, Images of Text](https://www.w3.org/WAI/WCAG22/Understanding/images-of-text.html); [W3C, Complex Images](https://www.w3.org/WAI/tutorials/images/complex/)).

Create a `TechnicalFigure` shell that accepts a figure number, localized title, localized caption, scope label, version label, and a visible details region. Under it, build a small family of static Astro components driven by typed data: `BoundaryMap`, `ProcessTree`, `FilesystemTree`, `LayerStack`, `RouteMap`, `StateMatrix`, and `EvidenceTerminal`. Use HTML and CSS for layers, trees, state matrices, and filesystem zones. Use inline SVG only for connectors and routes whose spatial relationships would become unclear in ordinary flow. Avoid a client-side diagram runtime unless interaction is essential.

Store topology and technical tokens in TypeScript or JSON. Store every human-language label, caption, alternative, and detailed explanation in the existing locale catalogs. A diagram item should reference stable identifiers such as `agent`, `project`, `hostHome`, `mountNamespace`, and `sharedKernel`, while the locale namespace supplies full phrases. Commands, flags, addresses, process names, and paths should render in `<code dir="ltr">` or `<bdi dir="ltr">`. Translated labels must grow naturally through `minmax()`, intrinsic sizing, and wrapping. Fixed SVG text boxes should be avoided.

Each technical subject needs the representation closest to its mechanism:

| Subject | Primary representation | Corroborating evidence | Accuracy guardrail |
|---|---|---|---|
| Whole-process containment | Nested semantic process tree inside a warm boundary | Short `ps`-style or launch transcript | Agent, hooks, MCP servers, and children are all shown inside; host home remains outside |
| Filesystem reach | HTML/CSS tree or zone map with visible, read-only, writable, and absent states | One denied `cat` result and one successful project write | “Absent” and “read-only” remain distinct; paths stay LTR |
| Network behavior | Numbered route schematic plus semantic table | One normalized route or connection result | Linux and macOS controls are separated; macOS host filtering is described only as TCP and CONNECT |
| Shared kernel | Flat stack of sandboxed processes and namespaces over one shared kernel | Adjacent list of isolated views and shared realities | No miniature computer or separate kernel appears inside the jail |
| Layered controls | Vertical mechanism stack | Exact mechanism names and canonical links | Each row states what it controls and one limit |
| Inside, blocked, opt-in | Reusable state matrix | Relevant flags or config values | Color is redundant with words, symbols, and border treatment |
| Authority and config merge | Ordered precedence ledger | Small TOML excerpt | Repository config can tighten and cannot open the sandbox |

Linux namespaces isolate views of resources, while containers continue to share the host kernel. Diagrams must therefore show separate process and resource views above a shared kernel, rather than a sealed independent machine ([Linux namespaces](https://man7.org/linux/man-pages/man7/namespaces.7.html); [Docker, What is a container?](https://docs.docker.com/get-started/docker-concepts/the-basics/what-is-a-container/)). Network figures should pair a route path with tabular fields because routing contains destination, next hop, interface, table, scope, and policy information that arrows alone cannot express ([ip-route(8)](https://man7.org/linux/man-pages/man8/ip-route.8.html)). Tables must use real header relationships, and any necessary two-dimensional overflow must remain contained within the figure rather than forcing page-level scrolling ([W3C, Tables Tutorial](https://www.w3.org/WAI/tutorials/tables/); [W3C, Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)).

The existing raster illustrations can remain temporarily where they communicate a verified fact, but they should lose automatic zoom and receive explicit figure metadata and a visible text equivalent. Replacement priority should be based on explanatory risk: shared kernel first, whole-process boundary second, network behavior third, authority and filesystem figures next, then lower-risk orientation scenes. Decorative imagery should use an empty alternative and carry no unique information. This synthesis reviewed the source prompt, rendering component, captions, and image inventory; final replacement decisions still require human visual inspection of each current asset.

## Measurable acceptance criteria: judge comprehension and traceability before taste

| Area | Acceptance criterion |
|---|---|
| **First-view comprehension** | In a moderated test with at least 10 developers unfamiliar with ai-jail, at least 8 correctly state within 15 seconds that ai-jail starts the coding agent inside an OS sandbox, preserves project access, hides broader host resources, and targets mistakes by a trusted agent. At least 8 choose a disposable VM when asked about knowingly hostile code. |
| **First action** | At least 8 of 10 test participants can identify the first install or run action without opening navigation, and at least 8 can find the threat model and configuration switches within one navigation decision. |
| **Product specificity** | Every major homepage section passes the logo-swap test: an internal review records the ai-jail mechanism represented by its palette, bars, artifact, and wording. No hero image, figure, or section survives review solely because it “looks technical” or “looks secure.” |
| **Claim traceability** | Every major claim is adjacent to at least one command, output fixture, numbered figure, dated fact, explicit limitation, source link, or verification route. Every command and output fixture records the ai-jail version used to verify it. Competitor claims retain a review date and source. |
| **Diagram fidelity** | Every diagram has a named technical owner or reviewer, a factual checklist, a concise localized name, a visible localized details block, and a canonical source. Removing color still leaves every state distinguishable. Shared-kernel figures show one shared kernel. Network figures distinguish Linux and macOS behavior. |
| **Reflow and zoom** | At 320 CSS pixels and at 400 percent zoom, there is no page-level horizontal scrolling. Necessary wide tables or route diagrams scroll only inside a labeled container. Text does not overlap, clip, or disappear under WCAG text-spacing overrides ([W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html); [W3C Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)). |
| **Color and contrast** | Existing text contrast checks continue to pass. Every required graphical boundary, line, focus indicator, and state marker reaches at least 3:1 against adjacent colors. Inside, blocked, and opt-in remain distinguishable through visible words and form as well as hue ([W3C Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html); [W3C Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)). |
| **Motion** | Every remaining animation has a written job tied to state, feedback, or continuity. The homepage contains at most one automatic explanatory sequence. There is no decorative parallax, ambient pulsing, routine zoom, or repeated scroll reveal. Reduced-motion and no-script modes expose all information and controls immediately. |
| **Keyboard and assistive technology** | All controls, tabs, accordions, copy actions, and diagram-details disclosures are keyboard operable with visible focus. Screen-reader review reaches a concise figure name and a structured equivalent without traversing decorative connectors. DOM order matches the explanation order in both LTR and RTL layouts. |
| **Localization** | All six locales contain real translations for every changed string. `npm run check:i18n` reports no stale keys and no English fallback. Commands, paths, flags, addresses, and protocol tokens remain LTR. Hebrew receives a human bidi and focus-order review; Japanese and Korean receive human line-break and label-fit review. |
| **Performance** | Capture a production baseline before implementation. The redesign must not increase total client JavaScript or Largest Contentful Paint at the 75th percentile. Removing routine GSAP behaviors and raster diagrams should reduce transferred bytes on the homepage. Any regression requires a documented functional justification. |
| **Technical framing** | Automated content checks and human review confirm there is no claim of native Windows support, independent-kernel isolation, protection from hostile code, replacement of a VM, third-party audits, or broader macOS host filtering than TCP and CONNECT. Project-run audits are labeled as such. |
| **Repository gates** | `npm run check:colors`, `npm run check:i18n`, and `npm run build` pass on every redesign branch. Every generated or structured figure is visually reviewed in six locales before merge. |

Preference testing can compare two visual compositions after these criteria pass. It should not decide whether the site is accurate, accessible, or authentic. The research does not establish that one style increases conversion, and aesthetic appeal can mask usability faults ([Nielsen Norman Group, Aesthetic-Usability Effect](https://www.nngroup.com/articles/aesthetic-usability-effect/)). The primary measures should therefore be comprehension, successful navigation, correct boundary choice, and evidence traceability.

## Conclusion

ai-jail already has the ingredients that generic developer-tool sites try to simulate: real operating-system mechanisms, commands developers can run, meaningful states, inspectable limitations, dated evidence, and a visual metaphor tied to the product. Its next design should expose those ingredients with less mediation. The memorable version of the site is the one where a warm boundary visibly changes what a cyan agent can reach, every figure survives technical review, and every claim offers a short path to verification.

The practical shift is from illustration-led marketing to evidence-led explanation. That change preserves the palette, the logo, the six-language architecture, the light and dark themes, and the candid 2.6 security framing. It removes the parts most likely to date quickly: ambient glow, generic isometry, repeated card grids, and motion used as finish. The resulting site can look more original because it looks more like ai-jail.
